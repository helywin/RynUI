# 原生国际化基础

108 阶段 1 提供 `ryn/i18n.hpp`、`ryn/config_provider.hpp` 和同一个窗口内配置上下文，已通过正式 MSVC HEADLESS Debug/Release 定向验证。组件族与服务的后续接入分别记录其实际证据；Form 消息来源迁移也已通过相关 Debug/Release 合同。默认 size/disabled/direction 的全面消费与 Gallery 双语仍按后续阶段追踪，不能据此将 107 ConfigProvider 整项标为完成。

## 公开用法

`examples/i18n_app/i18n_app.cpp` 是只使用公开头的真实应用定义；将其 `content(model)` 传给通常的窗口 host。它挂载 ConfigProvider、响应式 Text、保留草稿的 Input、切换语言/计数的 Button，以及独立格式语言的嵌套 Provider。`rynui_i18n_public_api_tests` 用 CPU host 挂载相同源码；该入口不创建窗口。

```cpp
const ryn::MessageKey selected{
    u8"app.selected",
    ryn::PluralMessage{u8"count", ryn::String{u8"{count} item"}, u8"{count} items"},
    {{u8"count", ryn::MessageArgType::UInt}}};
const ryn::MessageCatalog messages({
    {ryn::locales::zh_CN, selected,
     ryn::PluralMessage{u8"count", std::nullopt, u8"{count} 项"}}});
ryn::Signal<ryn::LocaleId> language{ryn::locales::zh_CN};
ryn::Signal<std::uint64_t> count{2};

ryn::ConfigProvider(
    ryn::ConfigProviderProps{}.locale(language).messages(messages),
    ryn::ConfigProviderContent{[=] {
        const auto tr = ryn::useI18n();
        ryn::Text(ryn::TextProps{}.content(tr.text(selected, ryn::bind([=] {
            return ryn::MessageArgs{{u8"count", count.get()}};
        }))));
    }});
```

`useI18n()` 在 mount 时捕获当前作用域和调用处组件的 lifetime。`translate(key, args)` 在事件中读取该活作用域的当前值；`text(key, Prop<MessageArgs>)` 返回 `Binding<String>`。业务 String、插入参数、Input 的 value/defaultValue 不会被自动翻译。不要在事件中再次调用 `useI18n()` 寻找某个“当前窗口”。

## 包、语言与来源

`LocaleId` 拥有自己的 ID，验证 ASCII 子标记并规范大小写，不承诺完整 BCP47 negotiation。内置固定默认是 en-US；明确 alias 为 en → en-US、zh/zh-Hans → zh-CN。zh-TW、zh-Hant 与其他未知 ID 保留 requested，effective 使用目录的 fallback，并返回 `UnknownLocale` 诊断，不报告简体中文已支持繁体。

`LocalePack` 接受完整 `LocaleData` 并深复制到共享不可变存储；`data()` 只返回 const 引用。复用的 Picker/Pagination/Transfer/Upload/Image/Form/Descriptions/QRCode Locale 声明移入纯数据头 `component_locales.hpp`，旧公开组件头继续提供同名类型。StatisticLocale 取自 107 Popup/Statistic 交接的原始数据声明，尚未整合其 Timer/数字组件行为。新增字段均位于旧 aggregate 字段之后。

内置 en-US/zh-CN 包包括 Common/Table/Cascader/ColorPicker、完整月/星期/Picker 操作和格式数据、Transfer 内部分页、Upload 内部图片预览及精确十进制数据。创建自定义包时复制一个已明确选择的基础包，再改所需字段：

```cpp
auto data = ryn::LocaleCatalog::builtin().pack(ryn::locales::en_US).data();
data.common.confirm = u8"Proceed";
const ryn::LocaleCatalog catalog({
    {ryn::LocaleId("en-GB"), ryn::LocalePack(std::move(data)), ryn::locales::en_US}});
```

新目录自动含两个内置包及 alias；自定义声明扩展这些值，不能重复同一身份。fallback/alias 的重复、循环、未知引用在构造时拒绝，所有包的 fallback 最终到 en-US。自定义完整语言包要明确声明 `IntegerPluralRule` 和实际 `formats.source`，不能借用英文规则假称其他语言的完整支持。没有进程级可变注册表，也不读写 C `setlocale`。

Provider 的 locale、formatLocale、catalog、messages、direction、size、disabled、theme 都有显式来源；未设置逐字段继承，显式 false 与 Auto 有效。没有祖先显式 formatLocale 时跟随当前 locale，祖先显式设置后由后代继承，最近显式值优先。默认 direction 为 LeftToRight，与语言独立；Text 的 Auto 仍表示段落自动方向。

messages 是最近在前的不可变词典层：对每个候选语言先查所有可见层，再查下一 fallback 语言，最后用 MessageKey 声明的英文 fallback。父 Provider 当前使用中文，不会让缺少英文 key 的子英文 Provider 意外查到中文。消息条目使用目录中真实包的规范 ID，显式空消息是有效内容；不使用英文文案比较来推断是否设置。

Theme-only 包装保留 config，ConfigProvider 保留当前 Theme；其 theme 属性复用既有堆化初始化和 ThemeScope，语言更新不解析 Theme。Provider 是透明配置作用域，不添加可绘制 Box 或布局 padding。它的 lifetime 归属包裹它的组件 slot/host；父 owner 销毁即退役。普通、before-child、语义文字、透明包装和延迟 append 均传递同一个上下文。

## 消息与错误

MessageKey 显式声明 ID、英文 fallback 与参数 schema。参数为 `String`、`int64_t`、`uint64_t`、`Decimal`；调用时需要使用与 schema 匹配的精确 variant 类型。无隐式翻译任意 String 的重载。

模板只接受 `{name}`、字面括号 `{{`/`}}`，插入的文本不再解析。每个非 selector 参数必须在每个分支声明并出现；复数 selector 必须是 UInt。重复/缺失/多余/错型参数、同 ID 不一致 schema、缺少 other 或 malformed 模板均拒绝。英语 one 分支用于 count=1，其余为 other；中文均为 other。首版不接受负数/小数复数、ordinal、gender、HTML 或 ICU 语法。

纯函数 `lookupMessage`、`formatMessage`、`tryTranslate`、`translate` 仅依赖数据，不需要窗口、renderer、SDL 或 Components。`lookupMessage` 对 raw ID 返回 `MessageLookupResult`；缺 key 是 typed MissingKey。已声明 MessageKey 的缺译使用英文 fallback，UI 不泄漏 raw ID。

`tryTranslate` 返回 `variant<String, I18nError>`；便利函数抛出 `I18nException`，可检查 `error().code`。诊断只保存 locale、消息身份和 category，不保存参数业务正文、文本正文或输出半截结果。非法输入不发布配置/文字，连续提交同一非法值仍报错，恢复合法值后可继续更新。异常不表示任意业务 observer 已执行部分副作用后会全树回滚。

`text` 使用现有 Memo 的 String 语义等值投影，订阅属于捕获 owner；相同内容的新目录 handle 不通知，未使用 key 的变化不触发对应 Text apply。失效 I18n/helper/Binding 明确报 StaleContext，不能转到另一窗口。上下文只在 owner 线程使用；纯目录和纯翻译函数可以在后台使用。

## Form 消息来源

Form `.required()` 与未提供 `FormRule.message` 保存 builtin 来源，当前反馈与 metadata 查询随有效 FormLocale 重投影；`.required(String)` 和显式 rule message 始终保留原文。`FormRule.message` 从 String 迁移为 `optional<String>`，常用赋值形式不变，直接读取改为检查/解引用或使用应用自定的 `value_or`；显式空 String 继续拒绝，缺省使用 `nullopt`。完整示例与覆盖优先级见 [Form 国际化迁移](form.md#内置消息literal-与国际化迁移)。

切语言不重新运行校验，不取消有效异步任务，不触发业务 change 或校验 deadline。已交付 FormResult 是 String 快照；当前 errors/warnings 和尚未交付的异步结果使用最新语言，validator/async/setFields 的业务消息为 literal。真实 Host/Provider 回归与两个独立公开头 TU 的验证结果见 [Form 阶段结果](../openspec/changes/108-20261107-add-native-i18n/evidence/form-windows.md)。

## 当前格式边界

App/Notice 的调用处活上下文入口与窗口/来源退役规则见 [App 与 Notice 服务](app.md)。`useApp()` 和 `useI18n()` 在同一个嵌套 Provider 中捕获后，可在事件中创建真实富内容通知；`NoticeHandle::update` 不替换未提供的新 slot，因此语言/Theme 更新保留 Input 草稿、选区与 composition。`rynui.i18n_service` 的 App/Notice 组合源码已提供，实际运行和完整 Modal/Drawer 服务集成仍由后续验收追踪，不计入阶段 1 的通过数量。

消息插值的整数和 Decimal 保留精度，不经过 double。`formatMessage` 是有限消息格式化接口，不是一个新的数字/日期 Intl。语言包已提供真实 StatisticLocale、Picker 公历格式与能力来源；数字 helper 和日期 helper 将在阶段 2 从既有精确数值路径/公历实现中抽取和适配，不从 Core 反向调用 Components，也不复制一套新算法。

内置两包使用十进制数字与当前公历，默认日期仍是 YYYY-MM-DD，中文月面板为 YYYY[年]M[月]。不支持货币、紧凑/科学计数、时区或 instant 转换；`formatLocale()` 报告实际格式来源。与所选翻译语言不同的格式来源通过 UnsupportedFormat 诊断明确表示。

## 自动入口与验收状态

三个入口在 `tests/CMakeLists.txt` 的 HEADLESS 公共位置注册一次：`rynui.i18n_catalog`、`rynui.i18n_context`、`rynui.i18n_public_api`，target 为对应 `rynui_i18n_*_tests`。源码覆盖目录/模板/精确参数/复数、所有 slot 入口与 captured append、两窗口、24 层、10k 等值、非法后恢复、重入/销毁及真实 retained Text/Input。Windows 测试入口设置 CRT 和进程错误模式以抑制错误对话框。

三个新入口及 Prop/reactive/Theme 定向回归已在正式 MSVC HEADLESS Debug/Release 各通过 9/9，架构边界另通过 1/1。最多两个编译任务，原 Theme golden 保持不变；本阶段没有 native/GUI/GPU、系统 IME 结论。见 [阶段结果](../openspec/changes/108-20261107-add-native-i18n/evidence/foundation-windows.md)。
