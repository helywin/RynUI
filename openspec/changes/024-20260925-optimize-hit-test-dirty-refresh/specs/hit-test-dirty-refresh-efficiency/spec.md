# Spec Delta

## Purpose

规定批量节点变化后的命中快照刷新结果与规模行为，使滚动等大量 transform 变化仍保持准确的交互目标、祖先裁剪和 eligibility，同时避免对每条交互记录重复扫描整批变化节点。

## ADDED Requirements

### Requirement: 批量节点刷新保持命中语义
系统 SHALL 在一批节点变化后，刷新节点自身及其后代的命中记录，同时保持 paint 顺序、父交互 eligibility、裁剪和已提交布局的现有语义。

#### Scenario: 祖先与后代同时变化
- **WHEN** 同一刷新批次含交互节点的祖先、后代和重复节点
- **THEN** 每条受影响记录在本轮至多刷新一次，命中结果与逐节点参考路径一致

#### Scenario: 无关节点变化
- **WHEN** 批次只包含不属于任何命中记录祖先链的节点
- **THEN** 快照不刷新无关记录，已存在的命中结果保持不变

### Requirement: 节点身份不得跨代混淆
系统 MUST 使用完整节点身份判断变化是否影响记录；slot 被销毁并复用后，旧 generation 的变化不得误刷新新节点记录。

#### Scenario: slot 复用
- **WHEN** 变化批次含旧 generation 的节点 ID，且相同 slot 已由新 generation 占用
- **THEN** 新节点记录不会因旧 ID 被视为受影响

### Requirement: 大批刷新工作随变化量和祖先链增长
系统 SHALL 对大批变化节点建立每轮可复用的成员判断，使每条命中记录的影响检查不再逐一遍历整批变化节点；少量变化节点 SHALL 保留无需新建大规模索引的路径。

#### Scenario: 固定交互集合扩大变化批次
- **WHEN** 在固定命中记录数和树深下增加不同变化节点数
- **THEN** 影响检查的工作由收集变化节点及沿记录祖先链判断组成，不产生记录数乘变化节点数的逐项比较

#### Scenario: 单个节点变化
- **WHEN** 稳态仅有一个节点变化
- **THEN** 刷新保持既有零分配和命中结果合同
